Appendix A — Glossary

Full glossary
Term Definition
Asset Any data, model file, code tool, or digital resource the team creates or relies on
Flood Modeller Pro (FMP) Hydraulic modelling software used for 1D/2D flood simulation
PDM Probability Distributed Model: a conceptual rainfall-runoff model
Flode The team’s internal R package (Flood Operations Development Environment)
Tier 3 / 2 / 1 Asset classification by operational criticality. Tier 3 = live forecasting, Tier 2 = analytical, Tier 1 = experimental
Semantic versioning Version numbering system: Major.Minor.Patch (e.g. 2.1.0). MAJOR = breaking change, MINOR = new functionality, PATCH = bug fix
Metadata Information describing a dataset or model: what it is, where it came from, when it was created
Calibration The process of adjusting model parameters so outputs match observed data
Tool Register A version-controlled record of all code tools with ownership, tier, and status
Model Register A version-controlled record of all flood models with ownership, tier, condition rating, and connections
Connection Register A version-controlled record of all active connections between models in the team’s operational system
Hydrometric Data Register The single consolidated record for all Bronze, Silver, and Gold datasets: provenance, QC records, and derivation records in one table
NSE / KGE / FAR Common hydrological model performance metrics: Nash-Sutcliffe Efficiency, Kling-Gupta Efficiency, False Alarm Ratio
renv.lock / poetry.lock Dependency lockfiles that pin exact package versions for reproducibility; renv for R, poetry for Python
CI Continuous Integration: automated checks (tests, linting) that run on every code change
Data Owner As defined in the Data Ownership Model (CDDO, 2023): a senior individual with dedicated accountability for a logical grouping of data and in-depth knowledge of the overall business strategy in their data remit
Data Steward As defined in the Data Ownership Model (CDDO, 2023): an operational expert responsible for day-to-day activities supporting the governance decisions made by Data Owners
Delegated Steward A practitioner to whom the Steward delegates hands-on technical governance work. The delegation recognises that G7 Stewards are often people managers whose strengths lie in oversight and decision-making rather than technical depth; the Delegated Steward brings the domain expertise to carry out the work: assessing code quality, reviewing model condition, evaluating data pipelines, conducting annual Tier 3 audits, and producing corrective action plans. Typically at G6 grade. Delegation does not transfer accountability: the Steward remains responsible for all decisions. Defined in the Governance Framework Role Summary table.
Data Custodian As defined in the Data Ownership Model (CDDO, 2023): an individual responsible for capturing, storing, and disposing of data in line with the Data Owner’s requirements
Information Asset Owner (IAO) A senior individual accountable for the security, content, quality, and distribution of an information asset (typically a database or IT system). Defined in Cabinet Office guidance (updated October 2025). See Section 2.3.6
Information Asset Manager (IAM) A delegated role working on behalf of the IAO, with regular responsibility for the proper management of information in their business area
Data catalogue A maintained record of agreed data definitions, entities, and attributes used across the team. See Section 2.11
Data lineage The documented chain showing where data came from, how it was transformed, and where it flows to
Bronze The first tier of the medallion framework. Raw, unmodified data exactly as received from the supplier
Silver The second tier. Quality-controlled data with flags applied and QC decisions documented
Gold The third tier. Formally approved analysis-ready products derived from Silver data. Includes aggregated statistics, calibration inputs, and ML training sets
Provenance The documented origin and history of a dataset: where it came from, when, how it was received, and what has been done to it
Rating curve The relationship between water level (stage) and flow (discharge) at a gauging station, used to derive flow from level measurements
Gap-filling Estimating values for missing time periods in a dataset using a documented method
Quality flag A code attached to each data value indicating its quality status (Good, Estimated, Suspect, Rejected, No data, Below detection)
Flatline A sequence of identical repeated values in a time series, typically indicating a sensor or telemetry malfunction
Medallion framework A data architecture pattern organising data into tiers of increasing quality and fitness for purpose. Adapted here for hydrological data management
Hydrometric Relating to the measurement of water: flows, levels, rainfall, and related variables
NRFA National River Flow Archive: the UK’s national repository of river flow data
Datum The vertical reference level to which water level measurements are made
Parquet A columnar file format used as the standard storage format for all hydrometric datasets. Supports typed columns, compression, and efficient partial reads
Delta Lake A storage layer built on Parquet that adds transactions, schema enforcement, and time-travel to tables in Databricks. Used for Bronze and Silver stores in DASH
Q-FAIR Quality, Findable, Accessible, Interoperable, Reusable: the Defra data standards aims that this framework implements by design
DPIA Data Protection Impact Assessment: required where processing of personal data may result in high risk to individuals
Data (Use and Access) Act 2025 UK legislation governing data use, access, and sharing; referenced in updated IAO guidance
CDDO Central Digital and Data Office: the government body responsible for the Data Ownership Model
Conventional Commits A commit message convention: <type>(<scope>): <description>. Permitted types: feat, fix, docs, refactor, test, chore
fastverse A suite of high-performance R packages (including data.table) that is the team’s default over the tidyverse
polars The team’s default Python data manipulation library, preferred over pandas for typed, high-performance tabular operations
ONNX Open Neural Network Exchange: the preferred format for archiving trained ML models intended for long-term operational use
Black Box model A data-driven model that relates inputs directly to outputs without representing physical processes; includes neural network and transfer function models
Condition rating A numerical score (0–10) produced by a model condition assessment, mapped to a descriptive rating from Critical to Good
Cascading system A modelling system where the outputs of one model become the inputs to one or more downstream models
Manual override point A defined point in a cascading system where an operator can substitute a model output with an observed or manually estimated value
BFI Base Flow Index: the proportion of river flow derived from groundwater or other slowly varying sources. Ranges from 0 to 1
Static catchment attributes Time-invariant descriptors of a catchment attached to an ML training set Gold product: area, BFI, elevation, soil type, and land cover
ML training set Gold A Gold product type holding Silver time series data at native 15-minute resolution with static catchment attributes attached. Distinct from aggregated Gold products
